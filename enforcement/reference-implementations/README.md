# Reference Implementations

Reference implementations demonstrate the correct application of approved standards.
They serve as authoritative examples for contributors, reviewers, and enforcement
engineers.

A reference implementation is not a suggestion — it is a canonical demonstration of
how the standard should be applied.

---

## Purpose

- Provide concrete examples of correct usage  
- Reduce ambiguity and interpretation drift  
- Support enforcement and adoption  
- Serve as test cases for CI and linter rules  

---

## What Belongs in This Directory

- Minimal, self‑contained examples demonstrating the standard  
- Before/after examples showing migration  
- Sample configurations, components, or architectural patterns  
- Documentation explaining why the example is correct  

---

## Principles

- Reference implementations MUST match the approved specification exactly  
- They MUST be kept up to date as standards evolve  
- They SHOULD be minimal, clear, and focused  
- They SHOULD be used as validation targets for enforcement  

---

## Steward Verification

The Steward ensures that:

- Reference implementations are correct and canonical  
- They align with the specification and enforcement rules  
- They remain updated through the Review cycle
