# Reviewer Checklist

Use this checklist during the Legitimize stage.  
If any item is “No”, the proposal is not ready to advance.

---

## 1. Problem & Scope

- [ ] Problem statement is explicit and concrete  
- [ ] Scope is clearly defined (what is in / out)  
- [ ] Proposal belongs at governance level (cross‑team impact)  

---

## 2. Goals, Non‑Goals, Rationale

- [ ] Goals are listed and testable  
- [ ] Non‑goals are explicit  
- [ ] Rationale explains *why this* and *why now*  
- [ ] Constraints (security, compliance, performance, UX, etc.) are documented  

---

## 3. Specification Quality

- [ ] Uses normative language (MUST / MUST NOT / SHOULD / MAY)  
- [ ] Rules are unambiguous and self‑contained  
- [ ] No hidden assumptions or tribal knowledge  
- [ ] No contradictions with existing standards  

---

## 4. Alternatives & Impact

- [ ] Alternatives considered are documented  
- [ ] Trade‑offs are clearly explained  
- [ ] Impact analysis covers teams, systems, and workflows  
- [ ] Risks and edge cases are identified  

---

## 5. Enforceability

- [ ] Proposal includes an initial enforcement strategy  
- [ ] Rules can be checked mechanically (CI, linters, scaffolds, etc.)  
- [ ] No requirement depends solely on manual policing  

---

## 6. Adoption & Migration

- [ ] Initial migration considerations are present  
- [ ] Proposal is realistically adoptable by affected teams  
- [ ] No “big bang” migration without justification  

---

## 7. Consistency & Alignment

- [ ] Aligns with governance charter and philosophy  
- [ ] Aligns with existing architecture and UX principles  
- [ ] No overlap or duplication with existing standards  

---

## 8. Documentation & Traceability

- [ ] All required sections of the standard template are filled  
- [ ] Links to related ADRs / standards are present  
- [ ] Changelog section exists (even if empty)  

---

## 9. Decision

- [ ] Decision recorded: Approve / Approve with Changes / Reject / Table  
- [ ] Rationale for decision documented  
- [ ] Required changes (if any) are explicit and actionable  

---

## 10. Steward Verification

- [ ] Steward confirms lifecycle compliance  
- [ ] Proposal is ready to move to Enforce (if approved)
